## 위험·누락과 조치

1. **확인된 결함 — 게이트 허위 통과.** `coord/coord.py`의 `cmd_tc_check`는 행의 성공 표시·빌드 문자열과 원문→보드 방향만 검사하고, 15개 고정 ID 집합의 양방향 일치·중복·원문 누락·증거 파일과 그 내용·빌드 SHA 실재 여부를 확인하지 않는다. A0 소유의 `coord/`에 수정 요청했다. 수정 전에는 이 명령 하나만으로 GO 금지. 수정 후 음성·중복·누락·실패·다른 빌드·가짜 증거를 포함한 회귀 검사 필요.
2. **계획 충돌.** `PLAN.md`의 A6 항목은 15/15가 아니어도 A0 DECISION 예외를 허용하나 `AGENTS.md` U5는 15/15가 아니면 제출 GO가 없다고 명시한다. 상위 규칙을 적용해 예외를 허용하지 않는다.
3. **계획상 위험 — 아직 결함으로 증명되지 않음.** TC 전체 GET 캐시는 접수 후 바뀌는 접수번호 필드에 오래된 결과를 돌려줄 수 있다. 새 대화에서 ID가 누락되었을 때 직전 ID 재사용은 케이스 혼선 가능성이 있다. 각각 캐시 무효화 및 경계 없는 입력 테스트가 필요하다.
4. **안전 응답과 잘림.** 50초 타임아웃과 정상 응답의 경합으로 중복 콜백이 없고, 450자 잘림이 핵심 조건·금액·이관번호를 지우지 않는지 실제 테스트 필요. 기준은 대회 화면의 60초·500자이지 내부 목표값 자체가 아니다.
5. **아직 없는 증거.** TC 15건 실측, 음성 원음 처리, 이미지 입력 E2E, 실계정 카카오 콜백, 배포 SHA, 프로세스 재시작·재부팅·재연결·메모리, 평가 계정 접근, 채널 옵션, 토큰·권한, 디브리프와 최종 GO. 시스템이 준비되면 독립 실행과 원인·결과·증거를 보드와 아티팩트에 누적해야 한다.
6. **R-004 기존 테스트**는 일회성 scratch 증거를 가리킨다. 원본 산출물이 남아 있는지 불명확하므로 성공 재현성을 별도 확인해야 한다.
