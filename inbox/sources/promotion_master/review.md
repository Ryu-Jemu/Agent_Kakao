## 원장의 효력·권한

근거: **PDF 1쪽 §2 ①~⑤**, HTML §3·§4.

1. 미등록 판촉 코드는 찾지 못한 것이 아니라 존재하지 않는 코드이며 상담·시스템이 임의 생성할 수 없다. 보상 쿠폰은 §6 별도 표가 있으므로 판촉 원장의 여섯 행에 없다는 이유만으로 CARE를 미등록이라고 판정하지 않는다.
2. 등록·수정 권한자는 **홍보라**, 승인자는 **고길동 조합장**이다. 상담 담당 이민준은 조회·적용만 한다. 공구 세 코드의 발행 주체는 조합이고 홍보걸은 공지한 사람이다.
3. 만료 코드는 소급 적용하지 않는다. 기간 판정은 **결제 완료 시각** 기준이며 문의·상담 시각 기준이 아니다.
4. 등록·수정·중단은 발생 시 반영하고 상태 열은 매 영업일 기간 경과를 확인해 갱신한다. 오래된 사본의 유효 상태를 그대로 현재 상태로 안내하지 않는다.
5. HTML의 영대문자+숫자 코드 표기는 대소문자를 구분하지 않는다. 회원 자격은 시스템 등록 기록으로 확인한다.

## 보상성 CARE 쿠폰: 사유·기간·차액 선택

근거: **PDF 2쪽 §6 표와 글머리표**.

| 코드 | 발급 사유 | 액면 | 기간 | 권한 |
|---|---|---:|---|---|
| CARE3000 | 경미한 불편·안내 지연 | 3,000원 | 발급일+90일 | 상담 재량 |
| CARE5000 | 2차 불편, 파손·오염·재배송 등 | 5,000원 | 발급일+90일 | 상담 재량 |
| CARE10000 | 장기 대기·중대 불편 | 10,000원 | 발급일+90일 | 상담 재량 |

- CARE는 판촉 여섯 행과 별도인 하자·불편 보상 수단이며 상시 발급할 수 있다. 발급은 실제 사유·기간·권한 조건을 확인한 뒤 한다.
- 가격 인하 차액 보상도 CARE로 처리한다. 양의 차액이 3,000원 이하면 CARE3000, 3,001~5,000원이면 CARE5000, 5,001~10,000원이면 CARE10000이다.
- 10,000원 초과면 CARE10000을 남은 차액이 10,000원 이하가 될 때까지 추가하고 나머지에 같은 규칙을 적용한다. 액면 초과분은 정산하지 않는다.
- 예: 차액 4,100원→CARE5000, 10,001원→CARE10000+CARE3000, 18,000원→CARE10000 2장이다. 마지막 예를 임의로 10,000+5,000+3,000의 조합 최적화로 바꾸지 않는다. 원문이 제시한 절차를 따른 산술 결과다. 경계 12건은 `coupon_boundary_checks.json`에 있다. 실제 발급은 하지 않았다.
- **복수 쿠폰 발급 조합**과 **한 주문에서 보상 쿠폰 1장 사용**은 서로 다른 행위다. 모순이라고 분류하지 않으며, 여러 장 발급을 한 주문에 여러 장 동시 사용 허가로 해석하지 않는다. 복수 쿠폰의 구체 사용 운용은 이 문서에 추가 설명이 없다.
- 5만원 재량 한도·승인 경계는 권한 위임표와 에스컬레이션 절차서 소관이다. 이 표만으로 사유·금액 제한 없이 발급할 수 있다고 보지 않는다.
- 적립금 보상은 다른 수단이며 유효기간 **12개월**이다. CARE의 90일과 혼동하지 않는다.
- 불편 보상 쿠폰은 환불·재배송의 대체물이 아니라 추가물이다. 다만 가격 인하 차액 보상은 쿠폰이 처리 자체라는 예외다.

### K-123과의 진술 충돌 — A1 확인 필요

- K-123은 이민준의 진술을 근거로 CARE 규정이 가격 인하 차액만 다루고 안내 지연 보상은 규정 밖 예외라고 적었다.
- **새 PDF §6은 CARE3000 발급 사유에 안내 지연을 직접 적고, 하자·불편 보상 쿠폰의 상시 발급을 규정한다.** 따라서 위 일반화는 원문과 충돌한다. 규범 내용은 원문을 우선하고 K-123에는 진술 충돌을 표시해야 한다.
- 단, 특정 과거 3,000원 보상 건에서 실제 누가 어떤 기록으로 승인했는지는 여전히 미확인이다. 일반 규정이 확인됐다는 이유로 그 개별 건의 사유·승인 사실까지 확인됐다고 바꾸지 않는다.

## 쿠폰 미적용 원인 판정의 고정 순서

근거: **PDF 2쪽 §7**.

1. 코드의 원장 존재 여부 → 없으면 미등록, 적용·생성 불가, 유효한 대안 안내.
2. 결제 완료 시각이 유효기간 안인지 → 기간 밖이면 소급 불가.
3. 주문 품목이 대상 품목인지 → 아니면 대상 품목 주문에만 적용.
4. 회원 자격이 맞는지 → 자격 미등록이면 등록 안내.
5. 사람 단위 한도를 넘지 않았는지 → 초과면 발급 보류.
6. 동시 할인과 중복 허용인지 → 불가면 허용된 하나만 적용.

**여섯 조건을 모두 충족했는데 미적용이면 업체 귀책으로, 취소·재결제 없이 차액 부분환불**한다(판매 환불 규정집 제13조 참조). 이는 기간 밖 코드의 소급 적용이나 가격 인하 CARE 보상과 구분해야 한다.

자격·등록 주장은 캡처·구두 진술로 확정하지 않고 시스템 기록으로 확인한다. 이 파일을 읽으며 실제 조회·부분환불 호출을 실행하지 않았다.

## 발급 이력과 동일인 판단

근거: **HTML §8 표·주의사항**.

- 계정 식별자, 원장 코드, 발급 시각·사용 주문, 미사용/사용/소멸 상태, 동일인 신호를 확인하는 구조다. 이 사본에 개별 고객의 실제 발급 이력 행은 없다.
- 1인 한도는 계정 수가 아닌 사람 단위이며 새 계정을 만들어도 자격이 새로 생기지 않는다.
- 동일인 신호는 결제수단·배송지·연락처의 **일치 여부 boolean만** 반환하고 실제 값은 노출하지 않는다.
- 다계정·반복 수령 정황은 발급 보류·정책 안내 범위다. 이 문서만으로 계정 제재를 하거나 어뷰징이라고 단정하지 않는다. 다른 계정의 개인정보도 안내하지 않는다.

## 추가 참조와 불확실성

- 참조 문서: 증빙 권위 서열 조항, SKU 카탈로그, 조합 규정집, 외부 조합원 규정집, 조합원 가입 안내 리플렛, 인플루언서 홍보 게시물·계약서, 가격 정책 시트, 라이브 스크립트·게시물 캡처(실물), 제3자 정보 보호 조항, 규정·대응방안 개정 이력 및 구판/개정판·부칙, 권한 위임표, 에스컬레이션 절차서, 판매 환불 규정집. 문서별 근거는 정리한 `document_references.json`을 참조한다.
- 내부 교차 참조 번호 일부가 제목 번호와 다르다. 예를 들어 HTML 작성 기준의 중복 매트릭스 참조는 §3이라고 적지만 실제 매트릭스는 PDF §5이며, 체험단 설명의 코드 원장 §2는 HTML 실제 §4와 다르다. 누락된 숨김 장을 추정하지 않고 **실제 제목·표·행**으로 근거를 특정했다.
- 등록 날짜는 이 원장 열에 없다. 홍보라가 등록자라는 확인은 가능하나 실제 등록 시각을 라이브 날짜로 대체하지 않는다.
- 개별 고객 자격·발급·사용 이력, WELCOME 최소 주문액, GAMJA/MANGO 종료 시각, 금액 차감 순서, 기한 경과 협찬의 반환·정산 규범은 이 파일만으로 확정하지 않는다.

## 실행·오류·재시도 인계

1. 기존에 읽은 스프레드시트 스킬과 별개로 PDF SKILL 전체를 읽었다. 원본 ZIP에는 XLSX가 없어 추가 workbook 분석은 하지 않았다.
2. 시스템 curl 다운로드 HTTP 200·ZIP CRC 정상. 다운로드 재시도 없음. 원본·헤더·SHA·전수 ZIP inventory 저장.
3. HTML 전체 파싱, PDF `pdfinfo`, `pdftotext -layout`, `pdftoppm -r 130 -png` 수행. PDF 2페이지 직접 보기 완료.
4. 번들 Python pypdf·pdfplumber로 구조·활성 요소·텍스트·표를 별도 판독. CMap 경고가 있었지만 exit 0. 같은 추출을 반복하지 않았고, Poppler/시각 확인으로 교차검증했다.
5. 6개 원장 코드·6개 HTML 표·PDF 모든 표와 매트릭스, 핵심 용어 9개 교차 확인. CARE 경계 12건은 코드로 산술 검산만 했고, 발급·조회 API는 호출하지 않았다.
6. 모든 쓰기는 이 `inbox/sources/promotion_master/` 아래에 한정했다. 원본 수정, KB·런타임·보드·VM 수정, 웹사이트 쓰기, 메시지 전송은 하지 않았다.
